    Gemini
    VS Code Extension は MetaTextEditor にしない方がいい VS Code 拡張の name（package.json）は小文字ハイフン繋ぎ（metatext-editor）＋ displayName: "MetaText Editor" が公式の王道です。vsix ファイルも metatext-editor-0.1.0.vsix になって綺麗です。
    .exe だけ MetaTextEditor.exe にしたい場合 「タスクマネージャーやエクスプローラーで MetaTextEditor.exe って見えた方が Windows アプリっぽい」という好みなら、tauri.conf.json に "mainBinaryName": "MetaTextEditor" を 1 行足すだけで変えられます（Cargo や他ファイルを触る必要なし）。metatext-editor.exe のままでも全く問題ないです。

    → VS Code Marketplace（metatext-editor）＋ displayName: "MetaText Editor"
    → Windows MetaTextEditor.exe

Gemin talk

1.VS Code / Antigravity 拡張の .vsix パッケージ化
F5 起動ではなく、普段使っている IDE にそのままインストールして spec_setting.csv 等で実戦ドッグフーディング開始できます。

2.GitHub プッシュ & CI/CD（GitHub Actions）構築
Push だけで Windows / Mac（ユニバーサル）の Tauri ビルドやテストが自動実行されるワークフローを整備します。

3.エディタ機能のさらなる磨き込み
列ヘッダーのラベル編集 GUI、Enum ドロップダウン選択、条件付き書式（rules）の GUI 編集、外部ファイル変更時の自動リロード、Shift-JIS 保存の完全対応など。


・GitHub Pages Wasmで動く？

    Web 化するときは Wasm になる？

    いいえ、Wasm は不要で純粋な JS / TypeScript（＋ Canvas ＋ Web Worker）のまま動きます。

    Tauri 側の Rust コード（lib.rs）はローカルファイルの読み書きだけの薄いラッパーにしてあり、100 万行パース・ソート・フィルター・JSONC パッチ・Canvas 描画はすべて TypeScript（@meta-csv/core + @meta-csv/ui）側に寄せてあります。
    実際に最初動かした apps/playground が、そのまま Web 版そのものです。

・PWA
    はい、余裕で動きますし相性抜群です！
    vite-plugin-pwa（manifest.json ＋ Service Worker）を足して Cloudflare Pages や GitHub Pages に静的デプロイするだけで：

    完全オフライン動作（サーバー通信ゼロなので、機密 CSV や 180 MB の巨大ファイルも外部送信せず安全に処理）
    ブラウザから「アプリとしてインストール」してウィンドウ単体で起動可能
    Chrome / Edge なら File System Access API でローカルファイルの直接読み書きにも対応可能（Safari / Firefox はダウンロード保存にフォールバック）

    なので、「普段使い＆自動 .meta.jsonc 連携は Tauri / VS Code 拡張、インストール不要のお試し・配布用は PWA（Web 版）」という 3 段構えが、ほぼ追加コストなしでそのまま実現できます！
